## 一、项目概述

### 1.1 项目背景与目标
在 FPS 游戏中，「命中部位」往往只影响伤害数值，玩家对此几乎没有直观感受。本项目的目标是把「部位受击」做成可感知的状态效果：玩家的头部、躯干、双臂、双腿在遭受相应攻击后，会产生不同的负面反馈（视觉遮挡、UI 变化、机动性下降、操作手感变差），以此体现「分部位破坏」的战术意义。
本项目不追求完整的游戏性，只追求效果可演示、可复现、可讲解。

### 1.2 核心思路
把角色模型划分为 5 类部位：头部、躯干（胸腹）、双臂、双腿。
每个部位受损后绑定一个独立的状态效果。
所有受伤均由程序按键触发（键盘调试按键），不需要敌人开枪，也不需要子弹命中判定。
前后端分离：后端负责状态与数值逻辑并预留接口，前端负责表现效果并接入接口。

### 3.2 各效果详细设计
（1）头部 —— 闪光弹 / 震撼弹白屏
触发条件：玩家遭受闪光弹或震撼弹，由调试按键模拟触发。
表现：屏幕瞬间被白色全屏遮罩覆盖 → 在约 1.5～3 秒内白屏透明度按曲线衰减 → 完全恢复。
可调参数：白屏初始透明度（1.0）、持续时间、衰减曲线（Ease Out）。
可选：白屏期间叠加耳鸣音效（非硬性要求）。
说明：头部不存在「受损」这一状态，只区分「遭受闪光弹」与「遭受震撼弹」两种情况。
（2）躯干（胸部）—— 持续流血扣血
触发条件：躯干进入受损状态。
表现：血条开始持续、按固定间隔扣血（例如每 0.5 秒扣 1 点）。
角色不会因流血直接死亡，扣血存在下限（例如不低于 1 点），或持续到使用治疗手段为止。
可调参数：流血间隔、单次扣血量、最低血量下限。
说明：躯干受损在视觉上表现较弱，效果主要体现在数值与 UI 上，因此由后端同学一并负责。
（3）双臂 —— 换弹速度变慢
触发条件：任意一只手臂进入受损状态。
表现：换弹时长被延长（例如 ×1.5 或 ×2.0）。
双手均受损时的叠加规则待定（可叠加，或统一取一个更慢的值）。
实现要点：以后端给出的「换弹速度倍率」为准进行乘算。
资源：换弹动画由李毕恺毅负责寻找与接入。
（4）双腿 —— 移动速度变慢
触发条件：任意一条腿进入受损状态。
表现：角色最大移动速度下降（例如 ×0.6）。
双腿均受损时的叠加规则待定（可叠加，或统一取一个更慢的值）。
实现要点：以后端给出的「移动速度倍率」为准进行乘算。

## 五、技术实现路径

### 5.1 总体架构：前后端分离
调试按键输入  →  后端（受伤逻辑 / 状态管理 / 数值计算）  →  接口 / 事件分发  →  前端（表现效果 / UI / 镜头 / 动画）

### 5.2 后端（林轩宇）
职责：
建立角色部位状态数据结构：头、躯干、左臂、右臂、左腿、右腿。
建立受伤入口函数：ApplyDamageToPart(部位, 伤害量)。
建立生命值系统：当前 HP / 最大 HP，以及躯干流血的持续扣血计时器。
计算并以接口形式对外暴露以下数据，供前端读取或监听：
血量百分比（0～1）
部位受损状态（布尔 / 枚举）
换弹速度倍率
移动速度倍率
闪光弹 / 震撼弹致盲触发事件
转向灵敏度倍率（为备选效果预留）
调试按键（示意，最终键位待定）：
要求：
逻辑与表现必须解耦：后端不直接操作 UI 控件与镜头，只负责发出信号。
所有可调数值（倍率、持续时间、扣血间隔）以变量形式暴露，便于现场调试。

### 5.3 前端（肖鹏希 / 李毕恺毅）
肖鹏希 —— 头部功能
制作全屏白屏遮罩（UMG 全屏 Image 或后处理材质），并实现淡出曲线。
监听后端的「闪光弹 / 震撼弹致盲」事件并播放效果。
可选：白屏期间叠加耳鸣音效。
李毕恺毅 —— 双臂 + 双腿功能
双臂：读取「换弹速度倍率」并作用于换弹流程（动画播放速率 / 换弹计时），负责寻找换弹动画资源。
双腿：读取「移动速度倍率」并作用于角色 Max Walk Speed。
制作右下角部位区块 UI 的状态刷新，与后端状态绑定。
制作左上角血条 UI 的刷新。

### 5.4 开发约束
项目使用蓝图新建，逻辑层采用 C++ 与蓝图结合的方式实现。
不做敌人、不做弹道、不做命中判定。
全部受伤由程序按键模拟触发。

## 九、验收标准
□  按下调试按键后，对应部位能进入受损状态。
□  遭受闪光弹 / 震撼弹 → 屏幕白屏并逐渐恢复。
□  躯干受损 → 血条持续扣血。
□  双臂受损 → 换弹明显变慢。
□  双腿受损 → 移动明显变慢。
□  UI 仅保留左上角血条与右下角部位区块，且颜色能正确反映状态。
□  可一键重置状态，支持反复演示。

## 十、风险与预案

## 十一、注意事项
头部不存在「受损」这一状态。头部只区分两种情况：遭受闪光弹、遭受震撼弹；两者的屏幕表现均按白屏 + 渐隐处理。
闪光弹 / 震撼弹是否对角色造成实际伤害（即是否扣血），目前尚未确定，待后续讨论明确后再补充到本文档。
右下角部位区块 UI 的方案 A / 方案 B 为二选一，由负责后端的同学在开发过程中确定，确定后需同步更新本文档并通知全体成员。
换弹动画资源由李毕恺毅负责寻找，需提前确认资源格式与 UE 版本兼容性。
项目全程严禁多人同时修改同一份工程文件，避免蓝图资产被覆盖。
