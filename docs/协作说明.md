# 协作说明

感谢参与这个部位受击 Demo。项目规模较小，协作以保持工程可运行、方便互相理解为目标，不要求复杂流程。

## 开发方式

仓库使用 Unreal Engine 5.8.3。建议每项功能使用一个独立分支，例如：

```text
feature/limb-effects
feature/weapon-reload
```

完成一个可以单独验证的小功能后，再向 `main` 提交 Pull Request。PR 中简单说明修改内容、涉及的文件或 UE 资产、测试方法和已知问题即可。

如果暂时不方便直接在原仓库创建分支，可以使用 Fork 开发，再提交 Pull Request。原作者或其他成员有时间时可以查看和合并，开发不必因为等待审核而停下。

## Unreal Engine 资产

蓝图、地图、动画蓝图和 UMG 等 UE 资产不适合多人同时修改。开始编辑某个公共资产前，建议在群里简单说明一下，完成后再同步结果，尽量减少互相覆盖。

提交包含 UE 资产的 PR 时，建议附上资产路径和简单验证步骤。因为二进制资产无法像 C++ 一样直观看到节点差异，截图或短视频会很有帮助。

## 任务拆分

建议一次只处理一个小闭环，例如：

- 腿部受损后移动速度下降，并在重置后恢复。
- 枪械能够正常射击和换弹。
- 双臂受损后换弹速度下降。
- 血条或部位状态 UI 刷新。

完成一个小功能后再继续下一个，便于定位问题和互相接手。

## 交流方式

遇到接口、资产或工程状态不确定时，直接在群里说明相关文件和现象即可。重要的接口变化、资产路径变化和已知问题，可以补充到 `docs/当前进度.md` 或 `docs/接口说明.md`，方便之后加入项目的成员了解情况。
